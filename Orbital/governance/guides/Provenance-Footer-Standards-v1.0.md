# **NDH‑Orbital Governance Guide**  
## **Provenance Footer Standards (v1.0)**  
### *Directive for Version Lineage, Supersession, and Archival Clarity*

---

## **1. Purpose**

This guide establishes the **required structure, tone, and content** for provenance footers used in NDH governance artifacts. Provenance footers ensure:

- clear version lineage,  
- explicit supersession status,  
- accurate archival context,  
- consistent cross‑repository interpretation.

Provenance footers are **not** narrative elements.  
They are **version identifiers**.

---

## **2. Scope**

These standards apply to all NDH governance artifacts, including:

- directives,  
- audits,  
- charters,  
- case studies,  
- pause notices,  
- routing rules.

They apply to all repositories governed by NDH‑Orbital.

---

## **3. Footer Categories**

Orbital Governance recognizes **three** provenance footer types.  
Each footer type must be used exactly as defined.

### **3.1 Legacy Footer**  
Used when the artifact represents the **original broadcast version**.

Required statements:

- Identify the artifact as the original version.  
- State that it is preserved for provenance only.  
- State that it is no longer active.  
- State that it has been superseded.

### **3.2 Superseded Footer**  
Used when the artifact represents a **version that was overwritten** or otherwise replaced.

Required statements:

- Identify the artifact as the overwritten version.  
- State that it is archived to document the overwrite event.  
- State that it is no longer active.  
- State that it has been superseded.

### **3.3 Active Footer**  
Used when the artifact represents the **current, authoritative version**.

Required statements:

- Identify the artifact as the active version.  
- State that it supersedes all earlier versions.  
- State that mirrored notices must reference this version.

---

## **4. Tone Requirements**

Provenance footers must be:

- concise,  
- factual,  
- unambiguous,  
- non‑expressive,  
- non‑narrative,  
- non‑cosmic,  
- non‑philosophical.

Hyperatlas may be expressive.  
Provenance footers must not be.

---

## **5. Prohibited Content**

Provenance footers must **not** include:

- governance theory,  
- evaluator semantics,  
- manifold descriptions,  
- meta‑analysis,  
- crossmaps,  
- lore,  
- extended prose,  
- recursive references,  
- routing logic,  
- VM behavior,  
- Sentinel invariants.

Provenance footers are **not** explanatory documents.

---

## **6. Standard Footer Templates**

The following templates are mandatory for all NDH governance artifacts.

### **6.1 Legacy Version Footer**

```
---
## Provenance — Legacy
This is the original version. It is preserved for provenance only and is no
longer active.
```

### **6.2 Superseded Version Footer**

```
---
## Provenance — Superseded
This version was overwritten and is archived to document the overwrite event.
It is no longer active.
```

### **6.3 Active Version Footer**

```
---
## Provenance — Active
This is the current and active version. It supersedes all earlier versions.
```

---

## **7. Governance Rationale**

Provenance footers maintain:

- version clarity,  
- evaluator lineage,  
- Sentinel invariant continuity,  
- cross‑repo consistency,  
- audit traceability.

They prevent:

- provenance bifurcation,  
- version ambiguity,  
- governance drift,  
- recursive documentation loops.

---

## **8. Enforcement**

All NDH governance artifacts must include a provenance footer conforming to this guide.  
Artifacts lacking compliant footers must be corrected before publication or mirroring.
