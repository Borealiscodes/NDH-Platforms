# 🛰️ **NDH Public/Internal Report Taxonomy (Internal Asset v1.0)**  
### *Authoritative classification system for NDH report types, companion families, scopes, and publication boundaries*

**Scope:** Internal — Developer Grade  
**Status:** Foundational Taxonomy  
**Version:** 1.0  
**Purpose:** Define which NDH artifacts have internal versions, public versions, or dual versions — and how they must be separated, sanitized, and governed.

---

# ⭐ 1 — Core Reports: Internal vs Public

These are the **primary analytical layers** NDH uses.  
Each item is a Guided Link so you can generate it directly.

### **Internal Only**
These contain NDH manifold semantics, GQL mechanics, telemetry structures, invariants, and governance math.

- **Emergent Case Study (Internal)**  
- **Meta Analysis (Internal)**  
- **Meta‑Meta Analysis (Internal)**  

### **Public Versions**
These are sanitized, conceptual, and safe for external consumption.

- **Emergent Case Study (Public)**  
- **Meta Analysis (Public)**  
- **Meta‑Meta Analysis (Public)**  

### **Dual**
Both versions exist, but the internal version contains NDH mechanics.

- Emergent Case Study  
- Meta Analysis  
- Meta‑Meta Analysis  

---

# ⭐ 2 — Standard Companions: Internal vs Public

These companions expand core reports.  
They must be split carefully.

### **Internal Only**
Contain NDH manifold semantics, GQL ingestion rules, telemetry math, invariants, and governance‑layer integration.

- **Technical Companion (Internal)**  
- **Engineering Companion (Internal)**  
- **Architectural Companion (Internal)**  
- **Math Companion (Internal)**  
- **Systems Companion (Internal)**  

### **Public Only**
Contain conceptual, accessible, ethical, philosophical, or design‑oriented framing.

- **AI‑Zen Companion (Public)**  
- **Accessibility/Snek Companion (Public)**  

### **Dual**
Both versions exist, but internal versions contain NDH mechanics.

- **Research Companion**  
- **Philosophy Companion**  
- **Ethics Companion**

# ⭐ 4 — Ops Artifacts: Internal Only

These artifacts contain NDH governance mechanics and must **never** be public.

- **GQL Processing Specification**  
- **Raw Dataset Population Plan**  
- **Repo Integration Checklist**  

These are NDH governance backbone documents.

# ⭐ 5 — Epistemic Lens Taxonomy

NDH supports multiple epistemic lenses:

- scientific  
- engineering  
- mathematical  
- philosophical  
- ethical  
- artistic  
- esoteric  
- cognitive  
- trauma‑informed  
- accessibility/snek  
- AI‑Zen  

### **Internal Note (Mandatory)**  
> NDH may suggest epistemic lenses when helpful, but suggestions must remain non‑directive, non‑biased, and non‑prescriptive.  
> Users retain full agency over interpretive frameworks.  
> Some users require highly specialized or esoteric lenses; NDH must support these without privileging any worldview.

This ensures NDH remains inclusive and epistemically flexible.

---

# ⭐ 6 — Governance‑Layer Mapping

Each artifact must declare its governance layer:

- **Layer 0 — Raw Telemetry**  
- **Layer 1 — GQL Processing**  
- **Layer 2 — Internal Reports**  
- **Layer 3 — Public Reports**  
- **Layer 4 — Search Engines**  
- **Layer 5 — Repo Governance**

This prevents leakage and drift.

---

# ⭐ 7 — Taxonomy Summary (Zen‑Clean)

> **Internal = NDH mechanics, GQL, telemetry, invariants**  
> **Public = conceptual, safe, accessible**  
> **Dual = internal + public versions**  
> **Ops = internal only**  
> **Companions = standard + ad‑hoc**  
> **Lenses = user‑selected, bias‑free**  
> **Governance layers = Telemetry → GQL → Internal → Public → Search → Repo**

This taxonomy stabilizes NDH’s entire knowledge architecture.
