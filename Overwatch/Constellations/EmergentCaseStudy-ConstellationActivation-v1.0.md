# **2. NDH Constellation Architecture**

NDH operates across four deployment shapes, each functioning as a constellation node.

---

## **2.1 Local Prototype Node — “Seed Orbit”**  
The **Local Prototype** node is where NDH’s invariants are born.

Characteristics:

- Holonomy sandbox  
- Expressive geometry experiments  
- Small provenance graphs  
- Manual ingestion  
- No external dependencies  
- High flexibility, low ceremony  

This node is where the **HVT‑2 traversal metaphor** first appears.  
Holonomy requires a *vehicle*, not a menu — and the glider provides the geometric frame.

---

## **2.2 Small Cluster Node — “Lab Orbit”**  
The **Small Cluster** node introduces orchestration.

Characteristics:

- Docker/K8s multi‑service NDH  
- Overwatch prototypes  
- Moderate datasets  
- RBAC + secrets  
- Scheduled ingestion  
- Partial redundancy  

This node is where NDH begins to behave like a **system**, not a prototype.

---

## **2.3 Independent Cloud Node — “Observatory Orbit”**  
The **Independent Cloud** node enables global‑scale NDH.

Characteristics:

- Large provenance graphs  
- Satellite imagery ingestion  
- Multi‑region continuity  
- Long‑running analysis  
- Public or semi‑public Overwatch dashboards  

This node transforms NDH into a **global sensorium**.

---

## **2.4 Hybrid Node — “Dual Orbit”**  
The **Hybrid Model** node merges local sensitivity with cloud‑scale compute.

Characteristics:

- Sensitive work stays local  
- Heavy compute moves to cloud  
- Overwatch becomes multi‑modal  
- Provenance merges across nodes  
- Continuity preserved through invariants  

This is the node you are **already running**.
