This roadmap defines the **directional architecture** for consolidating and governing NDH’s citation, verification, and tooling layers across the broader NDH ecosystem. - NDH‑CORE (mythos codex, holonomy ladders, recursion‑safety systems)

- **move IDE hooks out of NDH‑TIDS**

## **3. Roadmap Objective**

To create a **governed, cross‑domain citation and verification architecture** that:

- uses **GQL** for citation graphing  
- uses **Sentinel** for policy enforcement  
- uses **Lean 4** for invariant verification  
- uses **VS Code hooks** for developer‑side enforcement  
- and does **not** place tooling inside NDH‑TIDS (which must remain governance‑only)

## **4. Roadmap Structure (Directional Only)**

### **4.1 Move IDE Hooks Out of NDH‑TIDS**
IDE hooks are **not** trauma‑informed governance.  
They belong in:

```
NDH-PLATFORMS/IDE-Hooks/
```

### **4.2 Place GQL Citation Graphing Inside NDH‑PLATFORMS**
GQL is a **platform‑level service**, not a governance artifact.

```

    schema.gql
    resolvers/
    ingestion/
    crossmap/
```

### **4.3 Sentinel Safeguards**
Sentinel policies should live in:

```

    provenance-policy.sentinel
    recursion-safety.sentinel
```

### **4.4 Lean Verification Layer**
Lean invariants should live in:

```
NDH-PLATFORMS/LeanVerification/
    citation-invariants.lean
    provenance-invariants.lean
    holonomy-invariants.lean
```

### **4.5 VS Code Enforcement Hooks**
VS Code hooks belong in:

```
NDH-PLATFORMS/IDE-Hooks/VSCode/

```

### **4.6 NDH‑TIDS Responsibilities**
NDH‑TIDS retains:

- trauma‑informed governance  
- reflective pauses  
- expressive safety  
- boundary alignment  
- non‑collapse epistemics  

NDH‑TIDS **does not** host:

- IDE hooks  
- GQL  
- Sentinel  
- Lean verification  
- tooling of any kind  

### **4.7 NDH‑CORE Integration**
NDH‑CORE provides:

- recursion‑safety principles  
- holonomy ladders  
- tile hierarchies  
- crossmap taxonomies  

These inform the **rules** used by Sentinel and Lean, but do not host the tooling.
