# **📄 NDH Expressive Suite Publication Envelope README v1.0**  
### *NDH‑Platforms → Public → README*

The **Publication Envelope** is the governed outer shell that contains all expressive‑layer PDF surfaces.  
This README explains the envelope’s purpose, structure, trauma‑informed semantics, and its role in NDH expressive governance.

---

## **1 — Purpose of the Publication Envelope**

The envelope exists to:

- unify all expressive‑layer PDF surfaces  
- provide a stable, reversible outer container  
- ensure trauma‑informed neutrality across the entire publication  
- prevent accidental hierarchy or urgency cues  
- preserve accessibility and metadata integrity  
- define the canonical order of expressive surfaces  

It is the **final structural authority** for expressive‑layer PDF assembly.

---

## **2 — What the Envelope Contains**

The envelope binds five governed surfaces:

- **Cover Page** — calm introduction  
- **Consolidated Layout** — full expressive suite overview  
- **Back Page** — gentle closing surface  
- **Publication Metadata Block** — identity + accessibility  
- **PDF Export Checklist** — final validation  

All five must be present for the envelope to be valid.

---

## **3 — Why NDH Uses an Envelope**

NDH’s expressive ecosystem is trauma‑informed and non‑hierarchical.  
A publication envelope ensures:

- **reversibility** — no surface implies “beginning” or “end”  
- **neutrality** — no surface is visually dominant  
- **consistency** — all expressive publications follow the same structure  
- **safety** — no urgency cues or evaluative symbolism  
- **accessibility** — metadata and alt text are preserved  

The envelope is a **gentle container**, not a frame or border.

---

## **4 — Envelope Geometry**

### **Page Order**
```
1. Cover Page
2. Consolidated Layout
3. Back Page
4. Metadata Block
5. Export Checklist
```

### **Alignment Rules**
- All surfaces centered  
- No asymmetry implying hierarchy  
- No directional flow  
- No evaluative ordering  

### **Margins**
- 40–60 px on all sides  
- No element touches page edges  

### **Color & Tone**
- Soft gray (#6A6A6A)  
- Pastel palette only  
- No saturated colors  
- No urgency cues  

---

## **5 — Trauma‑Informed Envelope Semantics**

The envelope must:

- preserve reversible geometry  
- avoid hierarchy  
- avoid urgency  
- avoid evaluative symbolism  
- avoid directional arrows  
- avoid “primary/secondary” language  
- avoid “final/end” language  
- maintain emotional neutrality  
- maintain equal visual weight across surfaces  

These invariants ensure the envelope remains safe and non‑hierarchical.

---

## **6 — Accessibility Requirements**

### **Alt Text**
Global alt text must describe:

```
A trauma-informed publication envelope containing the NDH Expressive Suite,
including cover, layout, back page, metadata, and export checklist surfaces.
All geometry is reversible and non-hierarchical.
```

### **Tagging**
- `<Section>` for each surface  
- `<Figure>` for images  
- `<Figcaption>` for captions  
- Metadata embedded in PDF properties  

### **Screen Reader Semantics**
Avoid ranking, ordering, or directional cues.

## **8 — How Contributors Should Use the Envelope**

Contributors should:

- treat the envelope as the **outermost governance layer**  
- assemble expressive PDFs strictly in envelope order  
- validate all trauma‑informed constraints  
- embed all metadata and alt text  
- run the export checklist before finalizing  
- avoid adding extra surfaces or reordering existing ones  

The envelope ensures NDH expressive publications remain consistent and safe.
