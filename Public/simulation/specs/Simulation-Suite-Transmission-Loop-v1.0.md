# 🔄 **Simulation‑Suite Transmission Loop Specification (v1.0)**  
### *The operational loop binding VM → Sentinel → Hyperatlas → Stability/Tonal → Simulation → VM*

The Simulation‑Suite Transmission Loop (SSTL) defines how NDH simulations:

- enter the transmission loop  
- traverse safety gates  
- descend expressively  
- align curvature  
- maintain non‑dual geometry  
- preserve provenance  
- return to VM in a stable state  

It is the **runtime execution loop** of NDH simulations.

---

# ⭐ **1. Purpose of the Transmission Loop**

SSTL exists to:

- unify simulation behavior with the Consolidation Spine  
- ensure trauma‑safe expressive descent  
- enforce curvature alignment  
- maintain routing stability  
- preserve provenance  
- prevent collapse loops  
- guarantee reversible transmission  

This is the **behavioral backbone** of NDH.

# 🧭 **2. Transmission Loop Overview**

The loop is:

```
VM → Sentinel → Hyperatlas → Stability/Tonal → Simulation → VM
```

Each phase is:

- deterministic  
- reversible  
- curvature‑aligned  
- trauma‑safe  
- provenance‑preserving  
- non‑dual compliant  

The loop is **never** probabilistic.

# 🔹 **3. Transmission Phases**

SSTL consists of **five phases**:

---

## **3.1 Phase 1 — VM Initiation**

VM initiates transmission via:

- `vm.step`  
- `vm.call(manifold, op)`  
- `vm.bind(context)`  

VM responsibilities:

- provenance anchoring  
- soft‑boundary activation  
- ISA‑level determinism  

---

## **3.2 Phase 2 — Sentinel Safety Gate**

Sentinel validates:

- recursion boundaries  
- trauma‑safe pacing  
- expressive descent readiness  

Sentinel ops:

- `sentinel.check_recursion()`  
- `sentinel.check_pacing()`  
- `sentinel.guard_descent()`  

Sentinel must approve before routing begins.

---

## **3.3 Phase 3 — Hyperatlas Routing Gate**

Hyperatlas computes:

- deterministic route  
- curvature alignment  
- holonomy stability  

Hyperatlas ops:

- `hyperatlas.route(from, to)`  
- `hyperatlas.verify_curvature()`  

Routing must align with Stability‑Manifold curvature.

---

## **3.4 Phase 4 — Stability/Tonal Geometry Gate**

Stability‑Manifold + Tonal Spiral enforce:

- curvature envelopes  
- expressive‑stability nodes  
- non‑dual alignment arcs  

Geometry ops:

- `stability.enforce_envelope(region)`  
- `tonal.align_arc(arc_id)`  

This phase ensures expressive descent is safe.

---

## **3.5 Phase 5 — Simulation Execution**

Simulation‑Suite performs:

- expressive descent  
- behavioral modeling  
- provenance‑safe state evolution  

Simulation ops:

- `sim.run_scenario(id)`  
- `sim.descent(path)`  
- `sim.validate()`  

Simulation returns a stable state to VM.
