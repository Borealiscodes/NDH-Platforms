### *Clarified: Conceptual Inheritance vs Textual Non‑Redundancy*

This artifact defines the **documentation‑layer provenance chain** for NDH governance.

It is external to the Omnibus Suite and referenced by **v1.3** and **v1.4**.

## ⭐ 1 — Provenance Chain Overview

NDH documentation follows a **forward‑only conceptual inheritance chain**:

```
v1.1 → v1.2 → v1.3 → v1.4
```

Each version:

- **inherits the purpose, structure, and governance role** of the previous version  
- **does not repeat or restate** earlier text  
- **references earlier versions without duplication**  
- **maintains documentation‑layer purity**  
- **preserves trauma‑informed clarity**  

This is the NDH documentation pattern:  
> **inherit conceptually, never repeat textually.**

## ⭐ 3 — Inheritance vs Redundancy (Explicit)

### **Conceptual Inheritance (Allowed)**  
Later versions inherit:

- structural purpose  
- governance role  
- provenance position  
- conceptual boundaries  
- documentation‑layer responsibilities  

This is **non‑textual** inheritance.

### **Textual Redundancy (Forbidden)**  
Later versions must not:

- restate earlier content  
- duplicate diagrams  
- re‑embed explanations  
- re‑describe prior logic  

This prevents drift, contradiction, and cognitive overload.

### **Clarification**  
> **Inheritance is conceptual.  
> Redundancy is textual.**

This keeps documentation stable, predictable, and trauma‑informed.
